# M6.5 — Metadata and generated-label localization implementation

**Updated:** 2026-10-29. **Stacked draft PR:** [#84](https://github.com/kandyman991/ReportMaker/pull/84), base frozen M6.1–M6.4 [#83](https://github.com/kandyman991/ReportMaker/pull/83). **Feature code/regression head before this checkpoint:** `ba791d0bb68b2e23f5f2ae307a7d561cdc6639c1`.

## Implemented in the dedicated M6.5 PR

1. **v5 ledger and non-destructive migrations.** `Report.localization_ledger` is the sole report-owned metadata/localization approval store. The strict v5 `report.localization_ledger` wire shape accepts only recognized persistable semantic keys, unique case-insensitive language tags and bounded `{text, source_sha256}` records. Generated-label English source strings and canonical `other_intervention_detail` are never duplicated. Old v1–v4 projects open with an empty ledger; Save As upgrades to v5 without overwriting the original. v4 **rich formatting remains required**, v3+ visual photo state remains required, corrupt/future versions fail closed, and the unchanged media-library/snapshot/asset rules still apply.
2. **Canonical guarded command and UI.** `set_metadata_translation` checks report generation, revision, selected target/primary preview language, key allowlist and exact source digest; each accepted approval is a single ProjectEditor history transaction with Undo/Redo. The manual `MetadataTranslationDialog` offers plain-text source and target fields, missing/outdated status, explicit Apply/Revert, and prevents unsaved draft navigation. The primary report language may be translated for generated label Preview even if not selected for ZIP export. No AI/automatic translation or browser access.
3. **Explicit transient template branding.** `ExportStyle.footer_source_language` and `footer_locale_approvals` are detached; neither belongs to `.rmproj`. V2 has an explicit user-operated footer language/translation control. An imported footer has unknown source language until declared, and cannot be silently relabelled from `Report.primary_language`. Switching projects resets all transient branding, as before.
4. **One locale context across customer outputs.** `resolve_export_metadata` validates the original canonical report before projecting translated body fields. Semantic keys cover DOCX/PDF Report Information, Summary, all **visible** info labels, selected intervention-type captions, `other_intervention_detail`, page prefix, generated Preview text, nested manual-break placeholders and footer prefix. The same detached mappings reach the editable DOCX writer, ReportLab PDF writer, schematic Preview and on-demand QtPdf proof. Proper names, frozen customer/site/machine snapshots, serials, technicians, ticket and ISO dates remain language-neutral source facts.
5. **Fail-closed multilingual ZIP.** Every language and format is validated before final destination replacement. An incomplete/blank/stale translation, missing footer provenance or renderer failure preserves an existing ZIP. The manifest now describes strict localized metadata instead of incorrectly promising English-only labels. V1 pure exporter defaults and browser-only ChatGPT remain untouched.
6. **Synthetic regression gates.** `test_v2_m65_catalog.py` (23 tests), `test_v2_m65_integration.py` (9 tests), `test_v2_m65_qt.py` (2 offscreen Qt tests), plus updated historical project/ZIP/template regressions. Windows Python 3.11/3.12 M6.5 staged, V2 M1–M6, V1/M1 smoke and M0 architecture workflows are retained on feature pushes. Covers Unicode/arbitrary tags, provenance, corrupt v5, v4 rich Save As, no source mutations, canonical undo, DOCX labels, PDF proof, ZIP rollback and UI drafts.
