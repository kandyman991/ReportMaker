# V2 M4 — Photo integration and project-owned media

**Date:** 2026-10-29. **Baseline:** verified main `a4f6e8834d41afe543a033a00739e6ab004088b7` after reviewed/merged PR #80. **Branch:** `feature/v2-m4-photo-integration`. **Scope contract:** M4 in `docs/v2/ROADMAP.md`; BE-E03/E04/E06, BE-U05/U06/U07, BE-I01/I03/I04 and photo safety in `docs/v2/BRANCH_EDITOR_REQUIREMENTS.md`.

## Implementation

1. **In-place photos/captions.** A canonical `PhotoBlock` now renders its project-owned working copy with the block's own non-destructive `PhotoVisual` (crop, rotation, flip, straighten, scaling/alignment and editable mark overlays) in a responsive, intrinsic-height branch thumbnail. Captions are natural-height inline drafts, with guarded Apply/Revert, stale-source notice and per-editor ownership through the single existing `DraftCoordinator`. Committed caption changes update original-language translations/staleness in the existing `LocalizedText` model. No image model or tree is duplicated.
2. **Editing and reuse.** Photo cards have explicit *Edit photo*, *Replace* (existing project media), and *From file* controls, plus contextual equivalents. V2 adapts the existing validated `PictureEditorDialog` with a visible, checked 10-tool icon ribbon rather than the V1 dropdown; V1 UI itself remains untouched. Modifying a photo changes only the selected placement's `PhotoVisual`; asset bytes and other placements stay intact. Replacement resets placement transforms only after an explicit warning if edits exist. Existing-photo reuse from M3.4 is retained.
3. **Native import/paste/drop.** A user may choose local files with the import dialog, invoke explicit Paste Image (Ctrl+Shift+V), or Copy-drop supported local image URLs from Explorer onto a valid module Inside or mixed content Before/After slot (including adjacent nested submodules). Reuse existing `media_import` conversion and `photo_gallery` MIME/path/pixel safety; do **not** decode clipboard HTML, remote URLs or arbitrary text, follow UNC/symlinks, or modify external originals. Files are read/converted before gateway commit; clipboard pixels become locally encoded PNG and use the same safe converter. A multi-file drop is staged and committed all-or-nothing, within the 64-file batch cap. Per-drop original generation/revision is frozen before an asynchronously queued import; a stale drag cannot create media in the new report.
4. **One transaction with asset history.** Added guarded commands for single/batch photo import+placement, replacement from existing/imported project media, visual edit and caption edit. Commands validate typed addresses, media bytes/labels, safe logical IDs, visual geometry, mixed indices and the prospective full `ReportProject`. Only once validation passes does a single `ProjectEditor` transaction update the canonical blocks; the same session revision atomically publishes the new immutable working bytes and library labels. A media snapshot ledger follows the editor's bounded undo/redo stack, so Undo removes an imported asset+placement and Redo restores the exact approved bytes; unrelated commands retain correct asset history and redo. .rmproj v4 save/load retains only active project-owned bytes; old external originals are never required to reopen.
5. **Compatibility.** Pure V2 core remains separate from Qt and V1 UI. Existing V1 media conversion, gallery security, photo composition/rendering, model and project archive schema are reused without modification. No new network requests, browser scripts, customer data transfer, AI automation, external CAD, or V1 browser behavior.

## Tests and acceptance

- `tests/test_v2_m4.py`: synthetic pure transaction and Qt-offscreen tests for mixed single/batch insert, immutable bytes, independent placement transforms, copy-only source handling, caption draft ownership, stale revision, save/reopen, preview height, annotation tool ribbon, native clipboard/drop and remote/HTML rejection. Retain all existing V2 drag/drop, natural-card, command, lifecycle and formatting regression coverage.
- `.github/workflows/v2-inline.yml`: explicit M4 test step on **hosted Windows Python 3.11 and 3.12**. Verify the **final PR head** after all code review corrections; local Linux/offscreen results do not replace actual installed-Windows inspection.
- Native installed Windows checks still required at 100/125/150% DPI: Explorer multi-drop across nested content, large HEIC/PNG/JPEG conversion, selection/focus on photo captions, keyboard action availability, no card overlap or workspace/internal scrollbars, full annotation-toolbar accessibility, and completed save/reopen.
- **M6 boundaries:** separate page Editor and Photo Gallery **tabs** are not yet installed in the V2 shell. Existing media library is reused and selected via explicit photo placement dialogs. The pre-existing `export.py` intentionally raises `ExportError` for edited visual layers until correct annotated DOCX/PDF export is implemented; M4 does not claim that exported appearance is complete or silently flatten photo edits. Full printable preview/export and cross-tab acceptance belong to M6, followed by M7 physical Windows release gates.
